# 실행 검증 기록

검증일: 2026-11-17 (KST)  
실행 환경: Python 표준 라이브러리만 사용, 외부 패키지 설치 없음

## 1. 자동 테스트

명령:

```powershell
python -m unittest discover -s tests -v
```

결과: **12개 테스트 모두 통과**

포함한 검증 항목은 Cross/X MAC 점수, epsilon 동점, 라벨 정규화, 3×3·5×5·13×13 생성기, 1차원 MAC 동등성, 잘못된 행렬, 잘못된 패턴 키, 필터 누락, 실제 `data.json` 6개 케이스, 학습용 누진세의 구간별 세액, 잘못된 세금 입력·구간 설정입니다.

## 2. data.json 일괄 분석

메뉴 `2`를 실행한 결과, 다음 6개가 모두 PASS였습니다.

| 케이스 | 판정 | expected | 결과 |
| --- | --- | --- | --- |
| size_5_1 | Cross | Cross (`+`에서 정규화) | PASS |
| size_5_2 | X | X (`x`에서 정규화) | PASS |
| size_13_1 | Cross | Cross | PASS |
| size_13_2 | X | X | PASS |
| size_25_1 | Cross | Cross | PASS |
| size_25_2 | X | X | PASS |

성능 표에는 3×3=9회, 5×5=25회, 13×13=169회, 25×25=625회의 MAC 위치 연산이 표시되었습니다. 실제 ms 수치는 컴퓨터의 당시 상태에 따라 달라질 수 있으므로, 평가 시에는 프로그램을 다시 실행해 본인 환경의 평균값을 확인합니다.

## 3. 입력 오류 재시도

메뉴 `1`에서 필터 A 첫 행에 숫자 두 개(`0 1`)만 입력했습니다. 프로그램은 다음 안내를 출력하고 필터 A 전체를 다시 받았습니다.

```text
입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.
필터 A 입력을 처음부터 다시 받습니다.
```

이는 행/열 개수 불일치와 숫자 변환 실패가 계산으로 넘어가지 않게 하는 최소 입력 검증입니다.

## 4. 보너스 실행

메뉴 `3`에서 `N=5`를 입력했습니다. Cross와 X를 자동 생성한 뒤, 2차원 MAC과 1차원 MAC의 점수가 모두 `1`로 같음을 확인했습니다. 두 방식은 동일한 입력과 100회 반복이라는 같은 조건으로 평균 시간을 비교합니다. 특정 방식이 항상 빠르다고 단정하지 않고, 실행 환경의 측정값을 보여 주는 방식입니다.

## 5. 학습용 누진세 계산 확장

메뉴 `4`에서 총소득 `50,000,000원`, 단순 공제액 `0원`을 넣어 실행했습니다. 프로그램은 예시 구간 세율로 다음처럼 계산 과정을 보여 주었습니다.

| 구간 | 구간 과세 금액 | 예시 세율 | 학습용 구간 세액 |
| --- | ---: | ---: | ---: |
| 0 ~ 10,000,000원 | 10,000,000원 | 5% | 500,000원 |
| 10,000,000 ~ 30,000,000원 | 20,000,000원 | 10% | 2,000,000원 |
| 30,000,000원 초과 | 20,000,000원 | 20% | 4,000,000원 |
| 합계 | 50,000,000원 | - | 6,500,000원 |

이 계산은 누진세의 “구간마다 해당 금액만 계산한다”는 구조를 보이는 학습 예시입니다. 화면과 README에 실제 신고·납부 판단에 사용하면 안 된다는 안내를 표시했으며, 실제 세액은 국세청의 해당 연도 공식 안내와 개인의 소득·공제 조건으로 확인해야 합니다.
