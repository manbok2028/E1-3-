# Mini NPU Simulator — MAC 패턴 판별기

3×3부터 25×25까지의 숫자 배열을 직접 곱하고 더해(**MAC**, Multiply-Accumulate) Cross와 X 패턴의 유사도를 판별하는 표준 라이브러리 전용 Python 콘솔 프로그램입니다.

### 과제 목표를 이 결과물로 어떻게 보여 주는가

1. **MAC 원리:** `npu.py`의 `mac_score()`가 같은 위치의 두 숫자를 곱한 뒤 모두 더합니다. 이것이 “모양이 얼마나 닮았는가”를 점수로 바꾸는 과정입니다.
2. **정확한 판정:** Cross 점수와 X 점수 중 큰 쪽을 고르되, 차이가 `1e-9`보다 작으면 계산 오차일 수 있으므로 `UNDECIDED`로 처리합니다.
3. **데이터 이해:** `size_5_1`처럼 적힌 키에서 크기 5를 읽어 `size_5` 필터를 연결합니다. `+`, `cross`, `x`라는 서로 다른 표현은 `Cross`, `X`라는 두 표준 이름으로 바꿉니다.
4. **성능 이해:** 3×3부터 25×25까지 각 칸을 한 번씩 방문합니다. 따라서 필요한 MAC 횟수가 9, 25, 169, 625로 늘어나며 시간 복잡도는 `O(N²)`입니다.
5. **문제 해결:** 데이터 모양·필터 크기·라벨이 잘못된 경우 전체 프로그램을 멈추지 않고 해당 케이스만 FAIL로 표시해 원인을 구분합니다.

## 1. 미션 목표를 쉬운 말로 정리

컴퓨터는 그림을 바로 이해하지 못하므로, Cross와 X를 0과 1이 들어 있는 칸(2차원 배열)으로 바꿉니다. 같은 위치의 숫자를 하나씩 곱하고 전부 더한 값이 MAC 점수입니다. Cross 필터 점수가 더 크면 Cross, X 필터 점수가 더 크면 X라고 판단합니다. 점수가 거의 같으면 억지로 고르지 않고 `UNDECIDED`로 처리합니다.

이 프로젝트는 다음을 직접 확인하게 합니다.

- MAC 연산이 AI의 필터 계산에서 왜 필요한지
- 키와 라벨 모양이 달라도(`+`, `cross`, `x`) 프로그램 안에서는 `Cross`, `X`로 통일하는 이유
- 소수점 오차 때문에 아주 작은 점수 차이는 동점으로 보아야 하는 이유
- 배열 한 변의 길이 `N`이 커질수록 칸 수가 `N²`개가 되어 반복 연산도 늘어나는 이유
- 문제가 생겼을 때 데이터·스키마, 로직, 수치 비교 문제를 나누어 진단하는 방법

자세한 평가자 설명은 [docs/evaluation-report.md](docs/evaluation-report.md)에 있습니다.

### 핵심 개념 사전

| 용어 | 쉬운 설명 | 이 프로젝트에서 하는 일 |
| --- | --- | --- |
| 2차원 배열 | 숫자가 표처럼 행과 열에 담긴 구조 | Cross와 X 모양을 `0`과 `1`로 저장합니다. |
| 필터(Filter) | 찾고 싶은 모양을 숫자로 만든 기준표 | Cross 필터와 X 필터를 패턴과 비교합니다. |
| MAC | 같은 칸끼리 곱한 뒤 전부 더하는 계산 | 점수가 클수록 해당 모양과 더 비슷하다고 봅니다. |
| 라벨 정규화 | 여러 표현을 한 가지 이름으로 통일하는 작업 | `+`, `cross`는 `Cross`로, `x`는 `X`로 바꿉니다. |
| epsilon | 거의 같은 두 실수를 동점으로 보는 작은 기준값 | 점수 차이가 `1e-9`보다 작으면 `UNDECIDED`입니다. |
| `O(N²)` | 한 변이 N인 표의 모든 N×N칸을 검사하는 증가 방식 | 크기가 커질수록 MAC 연산 횟수가 제곱으로 늘어납니다. |

## 4. 구현 요약

### MAC 연산

`npu.py`의 `mac_score()`는 중첩 `for` 반복문으로 같은 좌표의 값을 곱해 합산합니다. NumPy, pandas 같은 외부 라이브러리는 사용하지 않습니다. `mac_score_flat()`은 보너스로 2차원 배열을 1차원으로 펼쳐 같은 결과를 계산합니다.

### 라벨 정규화와 동점 정책

`normalize_label()`은 데이터의 `+`, `cross`, `x`를 프로그램의 표준 라벨 `Cross`, `X`로 바꿉니다. `decide_label()`은 `abs(cross_score - x_score) < 1e-9`이면 `UNDECIDED`를 돌려줍니다. 따라서 표시 방식 차이나 아주 작은 부동소수점 흔들림 때문에 오판하지 않습니다.

### 안전한 data.json 분석

`size_{N}_{idx}` 키에서 `N`을 읽어 `filters.size_N`을 고릅니다. 각 필터·패턴이 정사각형인지, 크기가 서로 같은지, 숫자인지 검사합니다. 한 케이스가 잘못되어도 전체 프로그램을 멈추지 않고 그 케이스만 `FAIL`과 사유로 기록합니다.

## 5. 결과 리포트

1. 제공한 `data.json`에는 5×5, 13×13, 25×25의 Cross/X 필터와 각 크기별 Cross/X 패턴이 있습니다.
2. 패턴의 expected 라벨은 `+`, `x`로 넣어 정규화 기능이 실제 데이터에서 실행되게 했습니다.
3. 필터 키의 `cross`, `x` 역시 `Cross`, `X`로 정규화합니다.
4. 정상 데이터는 각 패턴의 더 높은 MAC 점수와 expected가 같으므로 PASS가 됩니다.
5. 동점 또는 epsilon보다 작은 차이는 `UNDECIDED`이며, expected가 Cross/X이면 FAIL로 명확히 보고됩니다.
6. 행 수·열 수·숫자 형식이 맞지 않는 직접 입력은 안내 문구를 보이고 해당 행렬 전체를 다시 받습니다.
7. JSON의 필터 누락, 잘못된 키, 행렬 크기 불일치는 프로그램 중단이 아니라 케이스별 FAIL 사유가 됩니다.
8. 따라서 실패가 0개인 정상 샘플 결과는 데이터를 무조건 믿어서가 아니라, 정규화·스키마·크기·epsilon 검사를 모두 통과했기 때문입니다.
9. 성능 표는 I/O를 제외하고 MAC 함수 호출만 10회 이상 반복해 평균 ms를 냅니다.
10. 한 변이 `N`인 배열은 `N×N`칸을 모두 한 번씩 방문하므로 MAC 한 번의 시간 복잡도는 `O(N²)`입니다.
11. 예를 들어 25×25는 625회 곱셈·누적이 필요하고, 5×5의 25회보다 이론상 25배 많은 칸을 계산합니다.
12. 실제 시간은 컴퓨터 상황에 따라 달라질 수 있지만, 표의 `연산 횟수(N²)`가 증가 원인을 재현 가능하게 보여 줍니다.

### 성능 표 해석: 왜 O(N²)인가

한 번의 측정 예시에서 표의 크기가 5×5에서 25×25로 커지면 연산 횟수는 25배 늘고, 측정 시간은 약 22.8배 늘었습니다. 연산량과 시간이 비슷한 비율로 늘었으므로 시간 복잡도는 `O(N²)`로 볼 수 있습니다. 이는 MAC 연산이 `N×N` 이중 반복문으로 모든 칸을 한 번씩 방문하기 때문입니다. 다만 3×3처럼 매우 짧은 시간은 운영체제와 컴퓨터 상태의 영향을 크게 받아 실행할 때마다 값이 달라질 수 있습니다. 따라서 이 프로그램은 시간 값만 보지 않고, 함께 출력되는 연산 횟수 `N²`도 근거로 사용합니다.

## 7. 세금 계산 확장 기능 안내

메뉴 `4`는 총소득과 단순 공제액을 입력하면 `과세표준 = max(0, 총소득 - 공제액)`을 만든 후, 각 구간에 해당하는 금액만 세율을 곱하는 **누진세 계산 원리**를 보여 줍니다. 결과 화면에는 구간별 과세 대상 금액, 적용 세율, 구간별 세액, 학습용 추정 세액을 순서대로 표시합니다.

중요: 이 기능의 세율 구간은 코드 학습을 위해 단순화한 예시이며, 실제 대한민국 소득세·지방소득세·연말정산·사업자 세금 계산 기능이 아닙니다. 실제 신고나 납부 판단에는 적용할 수 없고, 반드시 해당 연도의 국세청 공식 안내와 개인별 소득·공제 요건을 확인해야 합니다.
